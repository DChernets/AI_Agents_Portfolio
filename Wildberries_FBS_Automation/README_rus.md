# Автоматизация FBS-поставок Wildberries и фулфилмента

**Production-система для ежедневной автономной сборки поставок, группировки заказов по региональным складам, поартикульной генерации стикеров и отгрузки на склад фулфилмента.**

---

## Бизнес-контекст

Заказчик — бренд электроники, электробритв и триммеров *Higher Energy*, работающий на маркетплейсе **Wildberries** по схеме **FBS (Fulfillment by Seller)**. Продажи идут по всей России с ежедневным объемом от 100 до 300+ заказов, распределяемых по 24 региональным логистическим узлам (Москва, Санкт-Петербург, Екатеринбург, Казань, Ростов, Краснодар, Новосибирск, Иркутск и др.).

По регламенту Wildberries все новые сборочные задания должны быть собраны, сгруппированы, оклеены штрихкодами и переведены в доставку строго каждое утро до 10:00 МСК. Задержка или невывоз влекут за собой крупные штрафы, снижение рейтинга продавца и блокировку склада.

**Как процесс выглядел вручную:**
1. Операционный менеджер каждое утро заходил в личный кабинет селлера на Wildberries.
2. Вручную выгружал сборочные задания, фильтровал отмены и сортировал заказы по 20+ городам.
3. Вручную создавал поставки в интерфейсе WB, добавлял туда заказы.
4. Вручную создавал короба (грузоместа `trbx`) для ПВЗ (Коледино).
5. Скачивал десятки разрозненных PDF-файлов со стикерами и штрихкодами.
6. Вручную рассчитывал сводку списания остатков для внесения в «МойСклад».
7. Отправлял архив файлов в чат сотрудникам 3PL-фулфилмента, постоянно перепроверяя, всё ли прикрепилось.

## Что делает система

Система полностью автономно работает на Linux VPS по расписанию systemd-таймеров в 2 фазы:

```mermaid
flowchart TD
    subgraph Фаза 1 ["Фаза 1: Сборка заказов в поставки (09:30 МСК)"]
        A["WB Orders API (GET /orders/new)"] --> B["Фильтр отменённых заказов"]
        B --> C["Группировка по 24+ FBS-складам"]
        C --> D["Race-Guard защита от дублей"]
        D --> E["Привязка заказов пачками по 100"]
        E --> F["Автодобавление коробов для ПВЗ"]
        F --> G["Пост-проверка состава (_verify_phase1)"]
        G --> H["Отчёт сборки в Telegram (09:30)"]
    end

    subgraph Фаза 2 ["Фаза 2: Доставка, документы и фулфилмент (09:44 МСК)"]
        I["Поставки в SQLite БД"] --> J["Перевод в доставку (PATCH /deliver)"]
        J --> K["Скачивание официальных WB QR"]
        K --> L["Генерация PDF стикеров (по артикулам с разделителями)"]
        K --> M["Генерация PDF QR поставок (58х40 мм)"]
        J --> N["Расчёт баланса списания (TXT)"]
        L & M --> O["Проверка целостности и страниц PDF (pypdf)"]
        O & N --> P["Отправка файлов в Telegram с retry-циклом"]
        P --> Q["Скользящая очистка логов и документов (30 дней)"]
    end

    Фаза 1 -->|Буфер времени для сборки на складе| Фаза 2
```

### 1. Фаза 1: Сборка и привязка заказов (09:30 МСК)
- **Сбор заказов:** Запрашивает сборочные задания из WB Marketplace API v3 (`GET /api/v3/orders/new`).
- **Фильтрация отмен:** Опрашивает статусы в реальном времени и исключает заказы, отменённые покупателями, отсекает не-FBS типы доставки.
- **Маршрутизация по складам:** Группирует заказы по 24 региональным складам (Обухово, Екатеринбург, Казань, Ростов, Волгоград, Новосибирск, Иркутск, Краснодар и др.).
- **Race-Guard защита:** Если менеджер успел создать часть поставок вручную в ЛК, бот не создаёт дубли, а находит существующие поставки текущего дня и докладывает заказы в них.
- **Логистические правила:** Автоматически добавляет 1 короб (`trbx`) для ПВЗ Коледино и пропускает короба для сортировочных центров (СЦ) по требованиям логистики.
- **Пост-проверка первого шага (`_verify_phase1`):** Сверяет состав созданных поставок через `order-ids` в WB API, проверяет наличие короба (при необходимости автоматически самовосстанавливает его) и аудирует остаток в `orders/new`.
- **Сводка в Telegram:** Отправляет в чат фулфилмента отчёт со статусом проверки и распределением по городам.

### 2. Фаза 2: Доставка, генерация документов и отправка (09:44 МСК)
- **Перевод в доставку:** Выполняет `PATCH /api/v3/supplies/{id}/deliver` по всем сформированным поставкам и скачивает официальные штрихкоды WB.
- **Целевой формат стикеров склада:** Собирает единый многостраничный PDF-файл (`{ДД.ММ} стикеры.pdf`):
  - Заказы сгруппированы строго по артикулу продавца.
  - Перед каждой партией товара размещается стикер-разделитель в рамке 58×40 мм: крупное название артикула и количество `[Артикул / N шт.]`.
  - Затем идут ровно `N` страниц официальных QR-стикеров заказов (58×40 мм). Лишние промежуточные стикеры исключены по запросу склада.
- **Единый файл QR поставок:** Генерирует `{ДД.ММ} поставки.pdf` со страницами 58×40 мм по одной на каждую поставку для приёмки на воротах склада.
- **Файл списания для 1С / МойСклад:** Формирует `{ДД.ММ} списание.txt` с точной суммой по каждому артикулу и разбивкой по городам для списания остатков в один клик.
- **Аудит файлов перед отправкой:** Через библиотеку `pypdf` проверяет читаемость PDF и строгое совпадение количества страниц (`N артикулов + M заказов` для стикеров, `N поставок` для куаров).
- **Надёжная отправка в Telegram:** Отправляет 2 PDF, TXT-списание и отчёт в чат фулфилмента через цикл повторных попыток (retries с backoff).
- **Политика хранения 30 дней:** Автоматическая ротация логов и скользящая очистка: файлы в `logs/`, `data/documents/` и события в SQLite старше 30 дней удаляются автоматически.

## Архитектура и надежность

### Работа на реальном проде без песочницы
У Wildberries нет тестовой среды для FBS-поставок. Запрос `PATCH /deliver` необратим и при ошибке накладывает штрафы за невывоз товаров.
- Разработана многоуровневая система безопасности: `OFF` -> `READ_ONLY` -> `DRY_RUN` -> `PILOT` -> `PILOT_DELIVER` -> `LIVE`.
- Это позволило безопасно протестировать и отладить систему прямо на боевом магазине заказчика.

### Spike-исследование логистики точек отгрузки
Официальная документация WB требует выбора точки отгрузки (`shippingPointId`). В ходе API-исследования выяснилось, что приёмка Wildberries автоматически привязывает точку к сортировочному центру при физическом сканировании QR-кода на воротах. Это позволило отказаться от нестабильных непубличных эндпоинтов и опереться на официальный API v3.

### Троттлинг и защита от лимитов WB API
Лимит WB составляет 300 запросов в минуту. В клиент встроен ограничитель интервала 250 мс, повторные попытки при кодах 429/500/502/503 и логирование полного JSON-ответа при ошибках 4xx/5xx.

### Аварийное оповещение оператора
При возникновении любого непредвиденного сбоя бот фиксирует полный traceback ошибки в лог, systemd и базу SQLite, и мгновенно отправляет тревожное сообщение в Telegram: `🚨 АВАРИЯ WB Agent: ...`.

## Технологический стек

| Область | Технологии |
|---|---|
| **Ядро** | Python 3.10+, FastAPI, Pydantic Settings, Click CLI |
| **API маркетплейса** | Wildberries Marketplace API v3, Content API v2, HTTPX (асинхронный клиент с троттлингом и retry) |
| **Обработка графики и PDF** | Pillow, pypdf (валидация структуры и страниц), python-barcode (Code128) |
| **Хранилище данных** | SQLite с потокобезопасной блокировкой, отслеживание состояний (`runs`, `run_events`, `supplies`) |
| **Доставка файлов** | Telegram Bot API (отправка документов с пулом повторных попыток) |
| **Инфраструктура** | Linux VPS, systemd таймеры и сервисы, logrotate, автоочистка 30 дней |
